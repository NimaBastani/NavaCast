NavaCast for 64-bit Windows
===========================

This folder contains navad.exe (the server), navactl.exe (the control CLI),
and navad.example.json (a sample configuration with no passwords).

NavaCast is released under the MIT License. The LICENSE file in the source
tree is the full text.

1. Copy navad.example.json to navad.json. Edit listen addresses and public
   URLs for this machine. Leave passwords out of the file.

2. Start the server from this folder:

     navad.exe --config navad.json

   The first start creates the owner and prints the username, password,
   and API token once. Store them. They are not shown again. That account
   stays the owner.

   To choose the first account yourself, set NAVA_ADMIN_USER and
   NAVA_ADMIN_PASSWORD in the environment before that first start. The
   password must be at least 8 characters. Do not put either value in
   navad.json.

3. Open http://127.0.0.1:8088 for the dashboard. The stream port (8000 in
   the sample) serves audio and HLS only. It does not serve the dashboard
   or the control API.

4. navactl.exe reads NAVA_API (default http://127.0.0.1:8088) and NAVA_TOKEN.
   Set NAVA_TOKEN to the token printed at first start.

5. The native MP3 encoder and the Opus encoder are linked into navad.exe.
   The ffmpeg encoder needs ffmpeg.exe on PATH. A new mount uses ffmpeg when
   that program is installed, and native MP3 otherwise.

6. Recordings are files under the data directory (data\recordings). Download them
   from the control API while signed in. They are not served from the stream port.

7. Closing the console window stops the process.

8. TeamSpeak. Open the TeamSpeak tab and add a bot: host, voice port (9987 unless
   the server uses another), and a nickname. Connect it, then click a channel in
   the live tree to join. On a station page, turn the public radio on or off and
   pick which bots that station feeds. Passwords stay blank after you save.
   Nothing extra listens on the stream port. Channel commands start with ! unless
   you change the prefix.

9. Users and quotas. The first admin is the owner and has no caps. Open the
   Users tab to create an account: a username, a password, a switch for each
   permission, and a number for each quota. Leave a quota box empty for no cap.
   Zero means that thing is not allowed. Hand the login to the person you are
   selling the account to. There is no payment provider. Disable stops that
   account from signing in, disconnects its TeamSpeak bots, and stops its mounts
   from taking new listeners. The process keeps running. Delete removes that
   account and its stations, mounts, playlists, library, recordings, schedules,
   and bots. A user sees only their own rows and cannot change their permissions
   or quotas. The owner can open one user and see what that account is running.

10. Bearer tokens. The Tokens tab is for the owner. Create a named token, set
    its switches, and optionally when it expires. The secret is shown once.
    Send it as Authorization: Bearer. It calls the same routes as a signed-in
    session: stations, mounts, play and pause, playlists, library, recordings,
    schedules, TeamSpeak bots, users, and listener kick. An owner token may
    manage users and other tokens, but it cannot grant a switch it does not
    have. A user token acts as one user and cannot exceed that user's
    permissions or quotas. Revoke or expiry makes the token dead immediately.
    A disabled user's tokens stop working. The server stores only a hash.

These binaries are 64-bit (PE32+). The GNU runtime is linked in, so they do
not need a separate copy of libgcc or libwinpthread.
